# Jerry’s Challenge · 技术方案

## 选型

采用 **Godot 4.7.2 stable + GDScript + Compatibility 渲染器**。编辑器与导出模板均使用 4.7.2 stable，工具下载在仓库 `.tools/godot/`，不提交 Git。

选择理由：本作需要原生 2D 场景、碰撞、动画、UI 和同键盘输入，Godot 已提供相应工具；节点与场景便于将玩家、机关、谜题和关卡分开实现。GDScript 便于直接使用引擎 API，首期不引入额外 .NET 环境。Compatibility 的功能范围适合本作像素 2D 场景，优先减少显卡兼容方面的额外要求；实际运行性能仍需目标电脑验证。

官方资料：[2D 工具](https://docs.godotengine.org/en/stable/tutorials/2d/introduction_to_2d.html)、[渲染器说明](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)、[MIT 许可](https://godotengine.org/license/)。

## 工程组织（实施规划）

```text
games/jerrys-challenge/
  project.godot
  scenes/
    menus/          # 标题、选人、暂停、结尾
    actors/         # 通用玩家场景
    levels/         # 每关独立场景
    interactables/  # 水果、篮子、拉杆、桥等
  scripts/
  assets/           # 本游戏实际使用的已授权素材
  licenses/         # 引擎与素材声明
```

当前已创建 `project.godot`、入口场景 `scenes/main.tscn`、主流程 `scripts/main.gd`、双人角色 `scripts/player.gd`、CC0 美术资源和许可文件。首个 demo 以主流程脚本组织四段关卡，尚未拆成上述完整目录结构；后续关卡增加时再按实际需要拆分。

## 关键实现约定

- 一个通用 Player 场景接收玩家编号、输入动作和外观配置，角色选择不复制整套行为代码。
- P1/P2 各自使用独立 Input Map 动作，任何谜题不要求两人长时间同时按住多个键。
- 谜题维护自己的状态，通过信号通知桥、门、UI；完成状态可保存，重复互动不破坏状态。
- 玩家显示名与角色外观独立，Jerry 可以选择任意外观。
- 像素纹理使用最近邻过滤；基准分辨率、整数缩放及窗口适配在原型内实际验证，避免先锁定未测试的比例。
- Windows 独立运行包为首个交付目标，导出后在开发编辑器之外验证双人完整通关。

## 当前状态

0.2.0 demo 已实现双人移动、四种角色选择、四段流程、合作限制、暂停、提示、静音、检查点存档和结尾。自动测试位于 `tests/smoke.gd`，覆盖模拟双人输入、桥梁碰撞、完整谜题推进及恢复流程；实际同键盘硬件冲突和儿童易用性仍需真人试玩。
