# Jerry’s Challenge 素材生成规格

使用系列共用的[本地素材生成指南](../../本地素材生成指南.md)。本页仅规定本游戏的美术和导入契约，其他游戏应建立自己的规格。

## 美术方向

温暖、可爱、适合孩子的双人合作像素横版冒险。与已有 Pixel Adventure 角色和地形保持相近的块面与细节密度：清楚的轮廓、圆润夸张比例、少量阴影。背景也要采用同一套粗像素语言，远景降低对比，避免写实天空、细碎树叶和插画式柔光。UI 使用游戏世界里的木框、铜件等材质。

先制作原创角色；Tom/Jerry 家庭自用角色的说明见 [Tom 与 Jerry 角色制作](Tom与Jerry角色制作.md)。参考素材必须逐项确认允许相应用途，不能把素材库里所有免费资源都送入模型。

## 角色交付规格

| 项目 | 规格 |
| --- | --- |
| 单帧 | 32×32 逻辑像素，RGBA PNG，透明背景 |
| 默认朝向 | 向右；当前程序通过水平翻转实现向左 |
| 主体 | 常规站立主体目标约 24–28 像素高；尾巴、耳朵、动作都要留边 |
| 坐标 | 原点为每帧左上角；根参考横坐标 x=16，常规站立脚底不透明像素到 y=29，下面留两行透明 |
| 缩放 | 全角色共用同一缩放与根坐标；跳跃姿态可按动作表偏移 |
| Idle | `Idle (32x32).png`，4 帧水平排列，128×32 |
| Run | `Run (32x32).png`，8 帧水平排列，256×32 |
| Jump | `Jump (32x32).png`，2 帧水平排列，64×32 |
| Fall | `Fall (32x32).png`，2 帧水平排列，64×32 |
| 帧率 | 当前播放器 Run 为 14 fps，其余为 8 fps，均循环播放 |
| 颜色 | 与角色母版一致的有限配色；最终像素默认无半透明平滑边 |
| 投影 | 不画进角色图片，游戏代码单独绘制 |

这是新素材的交付标准，不代表现有素材全部以同一方式绘制。当前播放器按 32 像素宽自动计算帧数，但首轮按上表固定数量制作。Jump/Fall 当前也循环，不能画成不可循环的长动作而不调整代码。当前角色以 2.5 倍绘制；逻辑精灵仍交付 32×32，不要预先放大图片。

最终路径为 `games/jerrys-challenge/assets/characters/<角色目录>/`。新名字还需要修改 `scripts/player.gd` 的皮肤登记并检查选人界面；候选阶段不得覆盖已有目录。

## 动作表起点

- Idle：稳定站立 → 轻微呼吸 → 回落 → 接回首帧；脚的位置保持稳定。
- Run：左右各一次接触、下沉、经过、腾空；合计八帧，头部与躯干起伏克制。
- Jump：上升姿态两帧，四肢与尾巴变化轻微；适合上升状态反复播放。
- Fall：下降姿态两帧，舒展准备落地；适合下降状态反复播放。

不逐帧变更脸型、服装、耳朵长度或颜色。完成后同时预览单帧原尺寸、最近邻放大、循环动图和真实游戏场景。

## 其他资源

地形沿用 16×16 逻辑格；新地形在独立测试图集验收接缝后再映射到关卡，不能直接替换现有图集布局。静态小道具先按 16×16 或 32×32 制作，逐任务明确尺寸、锚点与动画帧数。

背景目前由游戏代码绘制粗像素天空与树林。如果改为图片背景，需要单独约定层数、视差、覆盖范围与拼接方式；不能把一张模型生成的风景图直接视为可用替换品。所有图像导入使用最近邻显示，避免平滑破坏现有像素风格。
